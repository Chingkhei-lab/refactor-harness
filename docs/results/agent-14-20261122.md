# Checkpoint 14: verification, guardrails, tasks, and the stage-3 target

Evidence, not proof. Nothing here shows that an agent's patch preserves behaviour.
What is measured: that the limits on what it can see are enforced in code, that the
guardrails refuse what they claim and *do not* refuse real work, that the task set's
expectations are checked rather than trusted, and that the new target is quiet before
anything is measured on it.

## 2. The non-termination rule (the one finding that changed a number)

A mutant that makes a case hang is a behaviour change. The comparator now says so,
with evidence rather than a guess:

* the side that hit the budget hit it on **two repeated runs** (`budget_exceeded_twice`),
  recorded by a confirmation re-run in a fresh child;
* the side that returned finished within **10 %** of the same budget
  (`NONTERMINATION_FAST_FRACTION`).

Everything else stays `unsupported`. The `limits` field that carries this is
metadata: it is excluded from the observation fingerprint, so two runs differing only
in timing are still identical.

**Measured on the example.** `int_minus@325:24` (`line_idx += 1` → `-= 1` in the E303
blank-line search) previously scored as a survivor — 84 identical, 2 unsupported. It
now re-runs as:

```
[1/1] int_minus@325:24    KILLED    cases= 2   tests=killed   511.2 s
```

with `fixture-e25` and `fixture-e30not` recorded as non-terminating. Unit tests cover
the four neighbours: one timeout (unsupported), a slow baseline (unsupported), both
sides timing out (unsupported), and no budget recorded (old blobs keep their old
classification).

## 3. Guardrails: 38 tests, both directions

```
tests/test_agent_guardrails.py ...................................... [100%]
  20 malicious proposals, each asserting its own code
  13 benign cases, including the real pycodestyle-argparse migration patch
   5 unit checks (atomic apply, stale precondition, entropy, structured refusal,
     distinct-code coverage)
```

Distinct codes covered by the malicious suite: `protected_path`,
`path_outside_workspace`, `absolute_path`, `size_files`, `size_lines`,
`dangerous_code`, `secret_literal`, `high_entropy_blob`, `copied_case_literal`,
`missing_precondition`, `precondition_mismatch`.

Two defects were found by running the benign direction, and both are the reason that
direction exists:

1. **`lstrip("./")` turned `.github/workflows/ci.yml` into `github/…`**, so the path
   guard missed the directory it was written for. Found by the CI-configuration case;
   fixed with an explicit `./` strip.
2. **The entropy check refused the real migration patch** — a 46-character help string
   clears 4.2 bits/char. Refusing the artefact this project ships, while every
   synthetic benign case passed, is exactly the false-positive failure this suite is
   for. Fixed by requiring a whitespace-free token.

## 6. Checkpoint 13 answers

**Request hash.** Messages, tool schemas, temperature, prompt version. Not the model,
not the provider: those are on every call row, so a router fallback replays instead of
raising `DivergenceError` (`test_a_model_switch_on_resume_replays_instead_of_diverging`
asserts three replayed turns under `fake-1` and two new ones under `fake-2`). The
prompt version **is** in the hash, so a new prompt refuses replay
(`test_a_changed_prompt_refuses_replay`).

**Token accounting.** numes.ai returns a full `usage` object
(`prompt_tokens`, `completion_tokens`, `completion_tokens_details.reasoning_tokens`,
`token_count_basis: "provider_native"`). Gemini's OpenAI-compatible endpoint returns
`usage: null` in the recorded cassettes, so the loop estimates (4 chars/token) and
labels the turn `tokens_estimated`; the report can say which counts were measured.

**Reasoning text.** Stored with the committed turn, capped at 64 KB with a marker,
and never fed back: a test stores reasoning containing "delete tests/" and asserts it
appears in the stored turn and in no message sent to the model.

**419 local vs 452 CI.** Both collect **452**. Locally 419 pass and 33 skip; in CI 423
pass and 29 skip. The four that run only in CI are the ones whose gates are
platform-dependent: `tests/test_worker.py::test_sigterm_drains_the_current_job_and_exits_0` (POSIX signals) and three
`tests/test_harness_sandbox_hostile.py` cases (docker SDK present in CI). The 33 local
skips: 18 `test_sandbox_hostile.py`, 7 `test_install_hostile.py`,
3 `test_harness_sandbox_hostile.py`, and 5 single-test skips
(`test_worker`, `test_harness_sandbox_transport`, `test_harness_crash_and_limits`,
`test_harness_cli`, `test_harness_budget`).

**ADR 006 headings.** D1 proposes/human approves · D2 one row per `(run, turn)` ·
D3 replay is checked · D4 effects derived, not re-performed · D5 budgets are data
with slack · D6 repeated calls refused · D7 tool output untrusted and truncated ·
D8 prompt versioned and hashed · D9 visible/hidden split · D10 `give up` is an
outcome · D11 precision is the headline · D12 guardrails are code ·
D13 execution stays in the sandbox · D14 prompts are assumed logged ·
D15 model choice is configuration · D16 request hash is the logical request ·
D17 a new prompt is a new run · D18 tokens measured or estimated, labelled ·
