# The behaviour harness on two real changes — final report

**Evidence, not proof of equivalence.** Everything below is what these cases did
under these controls on these trees. It does not say that two versions of a
program behave the same, and the places where the harness is blind are listed
explicitly (§7) rather than left to be inferred from a percentage.

Date: 2026-11-20, revised 2026-11-21 after the mutation audit
(`docs/results/checkpoint12b-audit-20261121.md`) · tags: `v0.2.2`, `v0.3`

| | target | change under test | cases | verdict |
| --- | --- | --- | --- | --- |
| Stage 1 | `parse` 1.22.4 | 12 refactors + 1 hand-seeded bug | 273 (+34 tuned) | clean on all 12, bug caught on 4 cases |
| Stage 2 | `pycodestyle` 2.15.0 | `optparse` → `argparse` migration | 79 (77 CLI + 2 api) | 142 identical, 16 different (8 approved), **0 unapproved** |

---

## 1. Stage 1 — `parse`, the calibration target

`parse` 1.22.4 (1 106 lines, zero dependencies, wheels only) was chosen as a
**calibration target, not a legacy codebase**: deliberately boring so a misbehaving
harness cannot hide behind an interesting target.

| measurement | value |
| --- | --- |
| cases | 273 (307 after tuning), hash `ed283159d51e35b3` — reproducible from code, see §6 of the audit |
| outcomes | 261 return / 12 exception / **0 unsupported** |
| A/A noise | **0** over 5 fixed and 5 shuffled passes |
| rules | **0** — the measured result for 0 noise, not an omission |
| coverage | lines 426/554, branches 163/246, combined 73.5 % |
| 12 harmless refactors (6 mechanical, 6 hand-written) | **all clean: 0 false positives** |
| 1 hand-seeded bug inside a harmless refactor (`-` → `+`) | **different on 4 cases** |

### Mutation, and the finding that matters

300 mutants sampled from 839 sites (seed 12), two oracles: the harness and the
upstream test suite.

| | killed | of 300 | 95 % CI |
| --- | --- | --- | --- |
| harness | 139 | 46.3 % | 41–52 % |
| upstream suite | 259 | 86.3 % | 82–90 % |
| union | 259 | 86.3 % | — |
| … of mutants on a line the cases execute | harness 138/203 = 68.0 % (61–74), suite 194/203 = 95.6 % (92–98) | | |

Contingency table: **both 139, harness-only 0, suite-only 120, neither 41.**

**On `parse` every harness kill is also a suite kill.** The case set adds no kill
power to a library that already has 109 tests — the 120 suite-only kills mark
exactly where it is blind. Stage 1's job was to prove the harness sees a change at
all, and can say "no change" without crying wolf; it was not to beat a mature
suite.

Two corrections from that checkpoint are part of the record:

* the oracle polarity was inverted at first (a summary line that meant "passed"
  was stored as "killed"), giving a suspicious 0-overlap; the table above is the
  corrected one, and every stored row's `tests_note` was asserted against the
  flipped value before it was written;
* a kill on an *unexecuted* line was found (`bool_flip@406:8` changes which lines
  run), which is why "covered" is a prior for survivors and never a proof. The
  audit then showed that with statement-span coverage this mutant is **not** on an
  unexecuted line at all: `coverage` lists statement lines, and the site sits on a
  continuation line of a multi-line `if`. Re-measured properly, **0 of 300**
  stage-1 kills sit on a line no case executes.

The whole stage-1 row was recomputed after the mutation audit with a mutator whose
mutants are one-line edits instead of whole-file re-prints: **every one of the 300
verdicts is identical**, site for site, and the case set is now the reproducible
`ed283159…` one. The 46.3 % / 86.3 % comparison, and the finding that every harness
kill is also a suite kill, survive the correction.

### Tuning, honestly labelled

Cases were tuned on the same 300 mutants and evaluated on 150 held-out mutants
(seed 99, 539 untouched sites):

| | first pass | tuned | gain |
| --- | --- | --- | --- |
| same 300 (overfit by construction) | 139/300 = 46.3 % | 180/300 = 60.0 % | +13.7 pp |
| held-out 150 | 58/150 = 38.7 % | **83/150 = 55.3 %** | **+16.6 pp** |

Held-out with the suite as second oracle: harness 83, suite 113, both 79,
**harness-only 4** — so on mutants the tuning never saw, the harness is not a
subset of the suite, and reaches **73 % of the suite's kill power with zero
hand-written assertions**.

Caveat that belongs to the claim: the held-out sites sit in the same functions as
the tuned clusters, so this measures **regional** coverage, not cross-target
generalisation.

### The 41 mutants both oracles missed

Reviewed by hand (`docs/results/mutation-both-missed-20261120.md`): **7
docstring-only, 33 real behaviour gaps, 1 candidate equivalent (not proven)**, and
**32 of the 41 sit on a line nothing executes**. The 33 were proved with probes
(`01/Feb/2024` → `01/Jan/2024`, `FixedTzOffset.__eq__` → `None`,
`Parser('{a}{b}').fixed_fields` → `None`, tz `+0059` → `ValueError`, …), so they
are case-set gaps, not equivalent mutants.

## 2. Stage 2 — a real migration

`pycodestyle` 2.15.0, `optparse` → `argparse`, written by hand as the change under
test: `harness/migrations/pycodestyle-argparse.patch`. Both artifacts are
hash-pinned and the module is proved byte-identical between the sdist (module under
test) and the tag tarball (runnable suite): `04d95f31…`, `module_identical: true`
(`scripts/pin_oracle.py`).

| measurement | value |
| --- | --- |
| cases | **79** (42 fixture excerpts + 35 option probes + 2 api snapshots), hash `8f04551c…` |
| A/A noise | **0** over **5 fixed + 5 shuffled** passes |
| coverage incl. subprocess | **lines 1225/1365 = 89.74 %, branches 661/800 = 82.62 %, combined 87.11 %**, 2/89 functions never entered |
| `get_parser` / `_main` | **23/23**, **16/16** covered |
| verify-change (2 rounds × 79) | **142 identical, 16 different (8 approved), 0 unapproved, 0 unsupported, 0 flaky, 0 stale** |
| approvals | 8, each bound to its diff by sha256 |
| upstream suite on the migrated tree | 4 failures (3 usage-text assertions, 1 `add_option` API break) |

The `api` cases (ADR 004 D10x) are what turned the `add_option` break from a
suite-only finding into a harness finding. A CLI case cannot see an API nobody
calls; a snapshot of the module surface and of what `get_parser()` returns can.

### The bug the harness caught, and kept

The first migration draft printed `pycodestyle 2.15.0` for `--version` instead of
`2.15.0` — argparse's habit, not optparse's. The case set caught it, it was fixed,
and **it was not approved**. The pre-fix report is kept as evidence
(`docs/results/verify-change-pycodestyle-20261120-argparse-prefix.json`).

### The approvals, in full

Eight distinct cases: six parser *text*, two the public parser surface. The two
**line-number** approvals this table used to carry are gone — the CLI observation
now projects a traceback to its type, message and frames, so a patch that adds
lines above `read_config` produces no difference at all. The report these rows come
from is `docs/results/verify-change-pycodestyle-20261121.{json,md}`, regenerated
after the `api` snapshot stopped carrying the path it was imported from; the
verdict counts are unchanged (142 / 16 / 8 / 0).

| case | what differs | kind |
| --- | --- | --- |
| `probe-help` | help layout, `usage:` case, positional section, `options:` | text |
| `probe-no-args` | `usage:` case, no blank line before `error:` | text |
| `probe-int-error` | `argument … invalid int value` vs `option … invalid integer value` | text |
| `probe-unknown` | `unrecognized arguments:` vs `no such option:` | text |
| `probe-jobs` | same, with the value echoed (case declared `unordered`) | text |
| `probe-blank-lines` | same wording for a non-existent option | text |
| `api-module` | `OptionParser` no longer exported, `argparse` is | public surface |
| `api-parser` | `get_parser()` returns `ArgumentParser`; `add_option`/`add_options`/`add_option_group` gone | public surface |

The two api approvals are the honest replacement for a footnote: they say the
migration changes the public parser object, name the attributes that changed, and
are counted as `different (approved)` — never as `equivalent`.

## 3. What the two oracles see on the same change

| difference | harness case | upstream suite | seen by |
| --- | --- | --- | --- |
| help/usage layout | `probe-help` | `test_print_usage` | **both** |
| empty command line text | `probe-no-args` | `test_check_noarg`, `test_check_diff` | **both** |
| **`get_parser()` returns `ArgumentParser`; `add_option` gone** | `api-module`, `api-parser` | `test_read_config_prefix` | **both** |
| invalid integer wording | `probe-int-error` | — | **harness only** |
| unknown-option wording | `probe-unknown` | — | **harness only** |
| `--jobs` rejected, value echoed | `probe-jobs` | — | **harness only** |
| `--max-blank-lines` rejected | `probe-blank-lines` | — | **harness only** |
| `register_check` validation (`args and args[0] in …`) | — | `test_register_invalid_check` | **suite only** |
| AST-check registration (`get_parameters(...) == ['self','tree']`) | — | `test_check_nullbytes` +2 | **suite only** |

The two bottom rows are measured, not asserted: they come from the mutation audit,
where two mutants were killed by the suite and by no case. Both are
`register_check` contracts — behaviour reachable only through the API.

The `add_option` row was originally **suite only**. The harness compares behaviour
through the command line, so it saw text and exit status and not the *shape of the
object* `get_parser()` returns; every line the failing test executes was covered by
the CLI cases, which is the point — **coverage is a prior, not a detector.** The
`api` case kind closed it: the snapshot records the type, the bases and the
attributes of what `get_parser()` returns, so the break is now an approved
difference with a witness instead of a footnote. What a snapshot still cannot do is
exercise a contract, which is why the two `register_check` rows remain suite-only.

## 4. Mutation on stage 2

Protocol fixed before the run, as in stage 1: 2 108 reachable sites enumerated,
100 sampled with a stratified scheme (at least 3 per operator family, rest
proportional), **seed 21 written into `plan.json` before the first mutant**, and
the upstream suite run against every mutant with `--import-mode=importlib` (without
it pytest's `prepend` mode shadows the mutant with the unmutated copy — the canary
that proves this is in `tests/test_harness_canary.py`).

The first run of this protocol reported 100/100 for both oracles. **That number
was wrong**, and it is kept in the record as the audited failure:
`docs/results/mutation-pycodestyle-20261120.json` and
`docs/results/checkpoint12b-audit-20261121.md`. The mutator re-printed the whole
module, so every mutant moved every line number and the two cases that print a
traceback differed for all of them. The corrected run:

| | killed | of 100 | 95 % CI (Wilson) |
| --- | --- | --- | --- |
| harness (79 cases, incl. 2 api snapshots) | **62** | **62.0 %** | 52.2–70.9 % |
| upstream suite (775 tests, full run) | **74** | **74.0 %** | 64.6–81.6 % |
| both / harness-only / suite-only / neither | 58 / **4** / 16 / 22 | | |

The audit behind those numbers (`scripts/mutation_audit.py`, same seed, same
sites):

* **no kill on a line no case executes** — the label is empty; the defective run
  had 15;
* the most frequent differing case appears 24 times, not 77, and the distribution
  is over fixtures rather than over two traceback cases;
* 11 kills differ on at least half the cases (mutants that break the tool
  broadly), 51 on between one and thirteen;
* 4 kills are the harness's alone, each on **one** case, each with a concrete
  behavioural witness (a missing E302 report, four spurious E502 reports, a
  message that lost its first character, a `TypeError` observed as a projected
  traceback);
* 16 are the suite's alone, and the two reviewed by hand are both
  `register_check` contracts — behaviour reachable only through the API, which
  the api snapshot records the *shape* of but does not exercise.

This is a much more useful result than a saturated 100 %. It says the case set
reaches 62 % of the mutants in a sample where the mature suite reaches 74 %, it
sees four things the suite does not, and the gap is concentrated in
`int_plus` (9/18) — constants inside thresholds that a 40-line fixture excerpt
does not reach.

Cost, measured after the fix: 29.1 s for one pass over 79 CLI cases, 0.5 s for the
tree copy, and the suite on top (9.3 s when it fails fast, up to 84.5 s for a
mutant that breaks 737 tests). The published 54 minutes for 100 mutants is
**32.4 s per mutant**, which is why the estimate of 41 minutes — 24.7 s × 100 on
the pass alone — was low.

The polarity-safe canaries are `scripts/mutation_canary.py`, now a CI step, and
`tests/fixtures/canary/` for the stage-1 layout: a broken mutant killed by both
oracles, a comment-only mutant survived by both, plus a whitespace canary, a
**re-print canary** (the one that would have caught the mutator defect: it must be
killed by nothing) and a docstring canary that must be seen by exactly the two api
cases.

## 6. Rules and approvals, counted

| target | rules | approvals | why |
| --- | --- | --- | --- |
| `parse` | **0** | 0 | 0 A/A noise under the shim; no field needed masking |
| `pycodestyle` | **0** | **8** | 0 A/A noise; the 8 are accepted *differences*, not equivalences |

A rule and an approval answer different questions: a rule says "these two values
are the same thing" (masked fields, timestamps, unordered lists); an approval says
"these two differ, here is the diff a human accepted". Nothing approved is counted
as `equivalent`, and an approval whose digest changes is **stale** and the case
returns to `different` — which happened twice during this checkpoint and was fixed
by re-deriving the approval, not by widening it.

## 7. What this harness cannot prove

1. **It cannot prove equivalence.** It reports what these cases did. `identical`
   on 273 cases is not "the same program".
2. **It cannot exercise a contract nobody's case calls.** The `add_option` break
   (§3) is the worked example: covered lines, unobserved contract. An api snapshot
   now records the *shape* of the surface — that is how the break became visible —
   but a snapshot cannot exercise behaviour, which is why two `register_check`
   contracts are still the suite's alone.
3. **Coverage is a prior, not a detector.** On `parse`, 32 of 41 both-missed
   mutants sat on unexecuted lines — and one kill sat on a line the *unmutated*
   case set never executes, because the mutation changed which lines run.
4. **It is not a fuzzer.** The cases are generated from fixtures and an option
   matrix; they do not explore input space, and the 33 proved case-set gaps on
   `parse` are exactly the input shapes nobody thought of.
5. **A kill rate is not a quality score.** On `parse` every harness kill is also a
   suite kill (harness-only 0 of 300); on `pycodestyle` it is 62 % against the
   suite's 74 % with 4 kills of its own. The useful question is *what each oracle
   observes*, not who kills more — and a kill rate is only as good as the evaluator
   that produced it, which checkpoint 12b's audit had to repair before any of these
   numbers meant anything.
6. **Held-out measures region, not generalisation.** The stage-1 held-out sites sit
   in the same functions as the tuned clusters.
7. **The sandbox bounds the process, not the semantics.** No network, read-only
   rootfs, dropped capabilities, cgroup limits and a size-capped tmpfs workspace are
   containment of *execution*; a target that writes a wrong answer is still inside
   the sandbox and still wrong.
8. **Numbers are host- and shim-bound.** 0.91 s of sandbox overhead per pass is this
   machine; a different daemon or filesystem moves it.

## 8. The harness's own reliability, measured

| property | evidence |
| --- | --- |
| A/A noise | 0 over 5 fixed + 5 shuffled passes on both targets |
| sandbox vs direct, 300 mutants | **300/300 verdicts, byte-identical observations, 0.91 s/pass** |
| hostile target | write outside workspace, network, 200-fork storm (stopped at 62), self-SIGKILL — all contained **and recorded as values** |
| oracle aliveness | clean tree passes, broken mutant fails, both targets, every CI build |
| evaluator canaries | comment / whitespace / re-print mutants killed by **nothing**; a docstring word seen by exactly the two api cases — `scripts/mutation_canary.py`, a CI step |
| mutator invariant | one contiguous edit on the site's line, enforced by `mutate()`, checked over all 2 108 `pycodestyle` sites and 839 `parse` sites |
| observation invariant | no target source and no import path in a value: a traceback is type, message and frames; an api snapshot replaces `HOME`/tmp/workspace/case-dir with markers. Both leaks were found by canaries, not by an oracle |
| mutation audit | no kill on a line no case executes, on either target (`scripts/mutation_audit.py`) |
| oracle identity | suite tarball and sdist module byte-identical, both hash-pinned |
| approvals | 8, digest-bound; stale detected and demonstrated |
| flaky cases | 0; one noise source found and removed at the source (a `mkdtemp` path printed by `-vv`) |
| CI (`4a6abdc`) | `ci` 406/377/29/0; `sandbox-hostile` 28/28 with a 30-mutant gate `30/30, byte-identical, 10.36 s/pass` |
| case-set identity | stage 1 regenerates to `ed283159…` byte-for-byte and a stale file is refused; stage 2 is `--check`ed in CI |
